Blaze Note Meeting API

Billing model changed on the public docs (fetched 18 Sep 2026). Earlier wiki text (from 9 Sep 2026) described app “credits,” a required Business plan with api_access, and a default rate limit of 120 requests/minute. The live developer docs now describe a separate API product billed in prepaid VND (hours and tokens), with no default rate limit. Prefer the current wording below; do not quote the old credit model.

Marketing page: “Meeting API — đưa AI họp vào sản phẩm của bạn.” “REST + WebSocket + webhooks để tạo phiên, stream transcript realtime, lấy tóm tắt/biên bản và đồng bộ sự kiện vào hệ thống của bạn.” Example call: POST /v1/meetings. “Xác thực bằng API key, scope theo tài nguyên — phù hợp tích hợp doanh nghiệp.” Source: https://note.blaze.vn/meeting-api

Developer docs (public HTML):

  • API host in the quickstart: https://note-api.blaze.vn
  • “Create an API key in the portal (Developer). Copy the secret once (sk_live_… / sk_test_…).”
  • Paths described: Platform API (create meeting, ingest or stream, then generate a summary on that meeting); AI API for text already held (POST /v1/summarize / translate / refine / tts); AI API realtime audio via one WebSocket (transcription and translation live).
  • Summary step in the Platform path: “When the meeting has a transcript, generate overview (billed on tokens)” — not “1 credit”.
  • Smoke test: GET /v1/me — “plan + prepaid balance left”.

Source: https://note.blaze.vn/developer/docs/quickstart

Auth: Authorization: Bearer or X-API-Key. Prefixes sk_live_… (Production) and sk_test_… (Test). “The full secret is shown once at creation.” “The API is a separate product from the meeting-note app, bought and metered on its own price book — audio hours and tokens, paid from a prepaid VND balance; an app plan grants nothing here.” Platform API: “the free tier is a sandbox: sk_test_… keys only. A live key needs a paid API plan, because that is what production meetings and storage are bought with.” AI API: “no sandbox and no plan. A key holding only ai:* scopes is minted sk_live_… on any tier: those calls are paid for in prepaid VND and touch nothing stored.” “sk_test_… keys are a separate world for data: they see only what the API itself created, so a meeting made in the browser app is 404 to a test key.” Source: https://note.blaze.vn/developer/docs/conventions

Rate limit / concurrency: “Rate limit: none by default. A key is limited only by the budget you put on it yourself (rate_limit_per_min when you mint it) — over that, 429 with Retry-After: 60.” “What is bounded instead is how much runs at once: 200 concurrent requests and 200 concurrent realtime streams per account.” Spend ceiling: “a period stops at 265.000.000₫ of AI usage. It is a safety stop, not an allowance — the prepaid balance is still what pays for a call.” GET /v1/me reports prepaid.period_spend_cap_minor alongside prepaid.period_spend_minor. Default scope *. Source: https://note.blaze.vn/developer/docs/conventions

What a call costs (two products “do not share a bill”):

  • Platform API — “the monthly plan plus storage of meetings you keep.” “Creating meetings, live capture, folders, speakers and voice enrolment are in the plan. You pay for how much meeting audio/transcript you keep. STT and LLM work is always the AI API, even when it writes into a meeting.”
  • AI API — “prepaid VND (hours and tokens). Empty balance returns 402.”
  • Realtime STT/translate: “5.300₫ / audio hour (× open flows)”
  • Async file transcription: “3.710₫ / audio hour (STT). Stored meeting bytes, if any, are Platform storage.”
  • Translate / summarize / refine / complete / report / chat: “input + output tokens (3.975₫ / 15.900₫ per million)”
  • TTS: “106₫ / 1,000 characters”
  • “Reads are free: listing and fetching meetings, transcripts, participants, speakers, folders, recordings, webhooks, records and job status cost nothing.”
  • “Charged before the work, refunded if it does not happen” (duplicate upload, unsupported format, full storage pool, AI service error, translation cache hit, etc.).
  • “There is no ceiling on how long a recording may be: a ten-hour file is a ten-hour bill, not a refusal.” When duration is unknown: “a four-hour hold is charged up front and settled down to the true length once the audio is decoded.”
  • Running out: 402 API_UNITS_EXHAUSTED “when the allowance and any prepaid packs are spent,” or 402 API_SPEND_CAP_REACHED “when pay-as-you-go is on and the period's spend ceiling is hit.”

Source: https://note.blaze.vn/developer/docs/conventions
